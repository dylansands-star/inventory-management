Request / Data Flow

1
User interacts with a filter
The shared FilterBar.vue component (backed by the useFilters.js composable) sets one of four filters: Time Period, Warehouse, Category, or Order Status.
2
View calls the API client
The active view (e.g. Dashboard.vue, Inventory.vue) calls a method on client/src/api.js, which serializes active filters into query params and issues an axios request to http://localhost:8001/api/*.
3
FastAPI filters in memory
main.py applies apply_filters() / filter_by_month() over the in-memory Python lists loaded by mock_data.py — no database or persistence layer.
4
Response validated against Pydantic models
Results are coerced through typed models (InventoryItem, Order, DemandForecast, etc.) before being serialized back to JSON.
5
Vue stores raw data, derives the rest
Raw API responses are stored in refs (allOrders, inventoryItems); everything the template renders — totals, chart series, KPI cards — is a computed() derived from those refs, so it recalculates automatically when filters change.

Frontend Structure

Views
Dashboard, Inventory, Orders, Demand, Backlog, Spending, Reports — one per route, page-level data loading.
Components
FilterBar, detail modals (Inventory, Product, Backlog, Cost), ProfileMenu — reusable across views.
Composables
useFilters (shared filter state), useAuth, useI18n — cross-cutting logic extracted from components.

Notes

This is a demo system: there is no database — all data lives in JSON files under server/data/ and is loaded into memory once at server startup by mock_data.py. Restarting the backend reloads data from disk; nothing written at runtime persists. CORS is wide open (allow_origins=["*"]), which is appropriate for local development only.
